This is SYNTAX ERROR IN 20, our Resurrection entry. Magazines in 1984 printed programs to type in, with a checksum on every line. We let a Kiro agent repair what OCR breaks, but only code decides whether a fix is true: the printed checksum, then a C64 that must run it.

II · the death

An LLM asked to "fix the listing" will happily invent a line that runs and is wrong.README · The Problem
A model guesses
A misprint, or an OCR misread, is enough: here OCR read PRINT as PRIMT and the quote as a trademark sign, and the C64 answers SYNTAX ERROR IN 20. Ask a language model to fix it and it will produce something that runs, which is not the same as what was printed.

III · the witness

The magazine left a witness on every line.

Σ codes of the line number and body, spaces 0, mod 256

“A match is evidence, never proof.”

43/43

lines reproduced on a real June 1984 page

Every printed line ends in a :rem checksum. Our implementation reproduces the magazine's sums on 43 of 43 lines of a real June 1984 page. But a mod-256 sum collides easily, so a match is evidence, never proof: that is why the C64 must also run the line.

A Kiro Pre Tool Use hook runs this gate before apply_patch reaches the MCP server, and a refusal exits 2 with its reason. The trademark sign is the best trap: its code, 8482, is 34 mod 256, a quote, so a raw sum matches. The gate drops characters no C64 key can type before it sums.
