REFUSED

REFUSED (R4.15): line 20 contains "™", which no C64 key types. The magazine's checksum is the sum of what the typist typed, so this cannot be the printed line; write the character the page shows (Gazette notation for control keys).

The ™ trap. OCR read the opening quote as ™, code 8482, which is 34 mod 256: a quote. Fix only the M and a raw sum matches (159 = 159) for a line the C64 never stores. The gate drops untypeable characters before it sums.

The model chooses where to look. Code decides what is true.

Questions a judge would ask.

Is the C64 on this page real?

The screens are recorded from c64-ready@3.4.0's screen memory during the run. This site serves no C64 ROM (rights not cleared), so nothing here runs on a C64 live; the stamp says "as recorded". The gate panel is live.

Can the agent cheat its way to IT LIVES?

No. An emptied line, an untypeable character or a rewrite is refused; a forced patch is never certified (eval cases 4 and 9). RESURRECTED needs matching checksums and a C64 re-RUN that reaches the title.

Does it work on a real 1984 page?

On the June 1984 Gazette's Random Number Test the agent reached TITLE-PATH RESURRECTED in 2 of 2 attempts; 19 of 28 lines are source-exact against a vision-read reference. The recording stays private until rights clear.

Why trust a 1984 checksum?

It sums the line number's digits and the body's codes, mod 256, spaces counting 0; ours reproduces it on 43 of 43 lines of a real June 1984 page. A match is evidence, never proof: sums collide. So the C64 must run the line too.

What is not measured yet?

As of 2026-11-25: eval cases 5 and 6, the held-out runs, and any outside user's listing. Everything here comes from recorded runs on one machine.
