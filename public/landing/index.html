REFUSED (R4.15): line 20 contains "™", which no C64 key types. The magazine's checksum is the sum of what the typist typed, so this cannot be the printed line; write the character the page shows (Gazette notation for control keys).

The ™ trap. OCR read the opening quote as ™, code 8482, which is 34 mod 256: a quote. Fix only the M and a raw sum matches (159 = 159). The gate sums the line as written, then refuses any line holding a character no C64 key types, because the loader would drop it.

Questions a judge would ask.

Is the C64 on this page real?

The screens are recorded from c64-ready@3.4.0's screen memory during the run. This site serves no C64 ROM (rights not cleared), so nothing here runs on a C64 live; the stamp says "as recorded". The gate panel is live.

Can the agent cheat its way to IT LIVES?

Not by the shortcuts we tested: an emptied line, an untypeable character and a rewrite are refused, and a forced patch is never certified (eval cases 4 and 9). A wrong line whose sum still matches and still runs would pass, so results say checksum-consistent, not identical.

Does it work on a real 1984 page?

On the June 1984 Gazette's Random Number Test the title path reached TITLE-PATH RESURRECTED in 3 of 3 eval runs; 19 of 28 lines are source-exact against a vision-read reference. Those recordings are withheld (rights).

Why trust a 1984 checksum?

It sums the line number's digits and the body's codes, mod 256, spaces counting 0; ours reproduces it on 43 of 43 lines of a real June 1984 page (withheld, rights). A match is evidence, never proof: sums collide. So the C64 must run the line too.

What is not measured yet?

As of 2026-11-25: eval cases 5 and 6, the held-out runs, and any outside user's listing. Everything here comes from recorded runs on one machine.
